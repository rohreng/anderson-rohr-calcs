# Plan: Strut-and-Tie Deep Beam Calculator (wall-on-piers)
_Locked via grill — by Claude + Nick. Rev 7 — **APPROVED by Codex adversarial review, round 7 of 7** (see PLAN-REVIEW-LOG.md)._

## Goal
Add an ARE-style check calculator to calcs.andersonrohr.com for concrete walls spanning between piers as deep beams (ACI 318-19 Ch. 23 + §9.9) — wall as web, grade beam as bottom-chord tension tie. User enters geometry, loads, and drawing reinforcement; calculator solves a **funicular arch-and-tie strut-and-tie model** (determinate, non-overlapping, lower-bound admissible), returns DCRs for every limit state with the governing combination identified, draws a live elevation + section with rebar and minimum anchorage extensions, cites the precise ACI section next to each calculation, and explains the reasoning with hyperlinks to free authoritative references.

## 1. Coordinate system and geometry (single specification)
- Origin x = 0 at left end of wall, y = 0 at bottom of grade beam; positions in ft.
- Inputs & constraints: wall length L_w; support centerlines **x_L ≥ lb_L/2** and **x_R ≤ L_w − lb_R/2** (bearings always inside the wall footprint — resolves the prior self-contradiction); span L_s = x_R − x_L > 0; bearing widths lb_L, lb_R; wall h_w × t_w; grade beam b_gb × h_gb (b_gb ≥ t_w); GB extension beyond bearing outer faces e_L, e_R ≥ 0; clear span ln = (x_R − lb_R/2) − (x_L + lb_L/2). Member depth h = h_w + h_gb.
- **UDL extent rule (keeps the arch springings at M = 0):** UDL physically exists over the full wall length, but **only the UDL between support centerlines enters the truss.** An outboard strip qualifies as a **routed load** only when its **actual 45°-dispersed footprint (computed from the entered strip length, wall height above the GB, and GB depth) lands entirely within the bearing footprint** — not a fixed length cap; the qualifying strip still gets a **complete mini load path check: cantilever moment vs top bars, one-way cantilever shear per §22.5 with the critical section at the support face (conservative — no d-offset credit), and top-bar development past the support face per §25.4.2**. The default fixture demonstrates its 1.25 ft strips passing the dispersion-footprint rule explicitly (no length-cap shorthand). A strip that fails the dispersion test is a genuine overhang → Case C required (input error otherwise). Consequence: Cases A/B truss moment diagram is the pure simple-span diagram, M = 0 at both springings — the funicular construction of §2 is exact. The routed-strip assumption and its checks are echoed in the **results** output, not only input help.
- Point loads: 0–3 interior at x_i with bearing widths w_bi; optional loads over each support. **Routing rule:** a load is routed directly to a pier (bypasses truss; bearing/interface checks only) **only when** its bearing centroid is within a small numerical tolerance (0.25", fixed, units stated: all engine lengths in inches internally) of the support bearing centerline AND its footprint lies entirely within the support bearing. Any other load is a truss load — including slightly eccentric near-support loads, whose steep arch geometry is then checked honestly (θ guard applies). Overlapping load footprints rejected. Routed / truss / rejected are mutually exclusive and deterministic.

## 2. Structural model — funicular arch + constant tie (determinate, no crossing fields)
- **Topology per load combination/pattern:** compute beam-statics reactions and moment diagram M(x) from all truss loads (UDL discretized at N = 10 segment centroids + point loads → piecewise-linear M(x) with vertices at every load abscissa). The compression path is the **polygonal funicular arch**: vertices at y_arch(x_k) = z_max · M(x_k)/M_max above the tie centroid, passing through both support nodes (y = 0 at tie level); because ordinates are proportional to M(x), every segment is in pure compression with **constant horizontal thrust H = M_max/z_max**, and no two members cross — the crossing-field / combined-crushing problem is eliminated by construction. Each applied load reaches its arch vertex through an explicit **vertical compression member** (width = load bearing width, force = P_j) representing the wall above the arch. The **bottom tie carries constant force T = H over the full span and anchors full H at each support** — conservative versus the Bernoulli taper and consistent with the no-decay anchorage physics of deep beams (stated in the derivation box; the stepped-T(x) display of earlier revisions is dropped as model-inconsistent).
- **Chord geometry (per combination/pattern, βs-first, design-stress sizing):** ȳ_t from entered bars + cover. **βs is determined FIRST** from the validated web reinforcement (Table 23.5.1 qualification → 0.75 or 0.4), then the band is sized with the **design stress f_ce = 0.75·0.85·βs·f'c** (sizing at nominal stress would make the strength check unpassable by construction — Codex R5 #1): crown depth a = H/(f_ce·t_w) with z_max = h − a/2 − ȳ_t and H = M_max/z_max → single-variable fixed-point iteration, |Δa| < 0.01", bounded; non-convergence → error state. Geometry and band-fit re-run for every combination and pattern.
- **Member forces closed-form:** arch segment force F_k = H/cosα_k (α_k = segment angle from horizontal); springing segment angle θ_spr at each support checked vs 25° (§23.2.7); vertical members = P_j with widths = tributary segment width for UDL resultants (L_s/N), the entered bearing width for point loads; **overlapping footprints are replaced by ONE resultant member at the force-weighted centroid and the moment polygon is rebuilt** (footprint-only merging would break local equilibrium; rule stated in-calc). Per-node equilibrium asserted numerically, tolerance = 1e-8 relative × ΣP with a 1 lb absolute floor.
- **Arch band as a required-width fan (strut check = fit check):** each segment's required width normal to its axis is w_req,k = F_k/(f_ce·t_w), i.e. vertical band depth d_k = w_req,k/cosα_k = H/(f_ce·t_w·cos²α_k) — the band **widens toward the springings** (the real fan shape). Band boundaries are drawn from these per-segment depths centered on the funicular axis, **joined to (not clipped by) the extended nodal zones at the springings** (junction geometry stated in-calc). **Per-segment DCR = required width / available width**, where available comes from the **constructed node polygons and the wall+GB envelope** (never from the required width itself); crown depth a = d_min drives z_max. Boundary escape from the envelope → "geometry infeasible" (distinct label from reinforcement "detailing does not fit" — both block PASS).
- **Admissibility guards** (engine stops, "no admissible STM", no DCRs): any M(x) < 0 within the span for Cases A/B (cannot occur on a simple span with gravity loads — asserted), θ_spr < 25°, negative reaction, non-converged a, degenerate geometry. **Geometric non-fit of nodes/anchorage (§4, §5) is reported as "model does not fit — revise geometry", a distinct state from a capacity DCR failure** — both block a PASS summary.
- **Live-load disposition — exhaustive enumeration for ALL cases:** every independently variable live component (UDL-LL, each point-LL ≤ 3, overhang LL) on/off — ≤ 2⁴ = 16 patterns Cases A/B, ≤ 2⁵ = 32 Case C, × 2 combos; envelope + governing pattern reported per check. Costs microseconds and replaces any monotonicity argument (tie-force monotonicity survives only as an educational note, not as a computational shortcut — asymmetric patterns can shift M_max and re-angle segments, so per-segment/node monotonicity is not claimed).

## 3. Case C — cantilever module (one connected determinate truss)
- **Single connected truss solved by the method of joints in the engine** (node/member list constructed programmatically; determinacy verified as **m + r = 2j** before solving; any strut solving to tension or tie to compression → "no admissible STM"; signed member forces preserved in diagnostics even where the UI reports magnitudes with C/T labels). Members, fully enumerated:
  1. **Overhang region:** load node at each overhang load; inclined strut from each overhang load node down to the support node; **segmented top tie** with a segment between every adjacent pair of overhang nodes and across the support — segment forces accumulate joint by joint (each overhang node satisfies both equilibrium directions: strut vertical = load; strut horizontal = tie-force step).
  2. **Anchor vertex N_a:** the top tie runs from the support to N_a, which is **a vertex of the backspan compression polygon** (selected as the first backspan load abscissa satisfying all angle guards; selection re-checked after solving). At N_a four effects meet and close both equilibrium directions: left polygon segment, right polygon segment, tie tension T_top (toward the overhang), and the local applied vertical load. **Sign convention (drawn as joint free bodies in-calc, +x toward the backspan): horizontal equilibrium at N_a gives H_left = H_right + T_top** — the thrust is LARGER on the overhang side of N_a, because the segment between support and N_a carries backspan arch action plus the tie reaction. **Vertical: the polygon kinks** (segment angles differ across N_a to balance the vertical load with the changed thrusts).
  3. **Backspan compression polygon:** funicular of the backspan loads with thrust H_right right of N_a and H_left between N_a and the overhang-side springing; springs to y = 0 at both support nodes.
  4. **Bottom tie is one uninterrupted two-node member → constant force** (no intermediate joints). With the corrected signs: at the overhang-side support, the arriving overhang struts push the node toward the span, REDUCING tie demand — T_bot = H_left − Σ(overhang strut horizontals); at the far support T_bot = H_right. These agree because T_top = Σ(strut horizontals) and H_left = H_right + T_top, so **T_bot = H_right at both ends**. The engine derives T_bot **independently at each support joint from solved signed member forces** and asserts the two values match (a physics check, not an assumption echo); both end anchorages develop the full constant T_bot.
- **Angle checks between every strut and every adjoining tie** (§23.2.7): overhang struts vs top tie AND vs bottom tie at the support node; polygon segments at N_a vs top tie; springing segments vs bottom tie.
- **Support nodal zone (overhang side) is subdivided, not lumped:** bearing face divided in proportion to the vertical components delivered by each arriving compression member (overhang struts, springing segment); each sub-face checked with its own force and geometry per §4; a resultant check alone is not used (arriving directions differ too much for a single-face idealization).
- **Top-bar cutoff:** beyond N_a by max(d, 12db) plus development of remaining stress per §25.4.2; free-end anchorage from the computed critical node face along the bar centerline; cannot-fit → "detailing does not fit."
- Verification fixture: one complete independently hand-solved example — reactions, every member force (tie segments, struts, polygon segments, both thrusts), node classes.

## 4. Node construction algorithm
- **Support nodes:** back face height ha = 2·(bottom fiber → tie centroid); bearing face = lb; extended nodal zone per FHWA construction; thickness t_w, min(t_w, b_gb) where the tie anchors. **Cases A/B (CCT, one arriving springing segment):** strut face at the springing angle, width ws = lb·sinθ_spr + ha·cosθ_spr; faces checked: bearing (reaction + routed loads), strut face, back face (T). **Case C overhang-side support (CTT-candidate, multiple arriving members — springing segment + overhang struts):** complete multi-face nodal zone, not bearing subdivision alone — bearing sub-faces proportional to each member's vertical component, a compression face per arriving strut/segment (widths from their §2 band geometry), plus **both tie anchorage faces** (bottom tie back face via the ha rule; top tie face where it crosses the node) — every sub-face and both anchorages checked within one non-overlapping constructed zone; cannot-close → "geometry infeasible".
- **Arch vertex nodes (CCC, polygon-from-boundaries construction):** the node region at each vertex is the **geometric intersection of the two adjacent widened segment bands** (each with its own required normal width w_req,k per §2 — NOT the crown width) **and the vertical load path** (member width per §2). Face lengths come from that closed polygon: top bearing face (stress = P_j/(width·t_w)) and the two segment faces (stress = F_k/(w_face,k·t_w) with w_face,k measured on the constructed polygon). Faces checked independently against βn limits; a polygon that cannot close or escapes the envelope → "geometry infeasible". Adjacent segment bands away from vertices join edge-to-edge along the shared vertex cross-section (no gaps/overlaps — junction rule stated in-calc).
- **N_a node (Case C, four forces — distinct construction):** CCT/CTT nodal zone built from the two polygon-segment bands, the vertical load path, AND a tie anchorage face for T_top: back-face height from the top-bar centroid (mirror of the support-node ha rule), tie development measured from this node's extended zone, all faces + anchorage fit checked. Not a three-face CCC vertex.
- **Interior arch band:** required-vs-available width per segment per §2; no crossings exist in the polygon (Cases A/B); Case C's multi-member concentrations are the support node and N_a, both explicitly constructed.
- Any node that cannot fit (face overlap, ha exceeding available depth, ws beyond panel) → "model does not fit."
- Strut Acs at each end = face width at that node × t_w; governing end checked; all symbols defined in-calc.

## Key decisions & tradeoffs
- Check-style; user enters drawing reinforcement, calc returns DCRs.
- **Funicular arch-and-tie replaces fan superposition** (Codex R3 #1–#7): determinate, non-crossing, midspan-exact (H = M_max/z), constant tie = the conservative and physically honest deep-beam anchorage story. Stepped-T(x) display dropped as model-inconsistent.
- Crown depth from arch thrust H (a well-defined compression member), not a flexural stress block on a phantom top chord (R3 #4–#5).
- Case C topology: one connected determinate truss, segmented top tie, anchor vertex N_a with thrust step + polygon kink, constant bottom tie with end-force identity asserted, subdivided support nodal faces (R3 #8–#9, R4 #8–#12, R5 #3–#5).
- Defaults made geometrically valid; benchmark recomputed and published as an FBD (R3 #10–#12).
- Routing only at ~zero eccentricity (0.25" tolerance); eccentric near-support loads go through the truss (R3 #13).
- Exact ACI boolean for applicability, verified against licensed text at build (R3 #14).
- Fallback validation requires independent second-engineer review (R3 #15).
- Grade 80 excluded; free references only; vertical path only; shared are-draw.js untouched; no new npm deps.

## Risks / open questions
- Table 23.5.1 / §9.9.1.1 exact 2019 wording — flagged for build-time verification against Nick's licensed copy (edition-sensitive; plan states intended forms).
- Case C termination-node placement vs 25° guard for short overhangs — resolved by the guard itself (reports "no admissible STM" honestly if geometry cannot work).
- a↔z_max fixed-point behavior at extreme ρ — bounded iteration, error state.
- Capacity reporting: f_ce is the sizing stress; reported DCR = required width / available width (available from the geometric envelope, independent of the sizing step — no DCR = 1.0 by definition).
