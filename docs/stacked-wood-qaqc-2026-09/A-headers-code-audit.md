## Summary (5 lines)

1. Eight findings are seal-blockers: the Southern Pine reference values are the pre-2013 set (Fb up to +40 %, Emin +13.7 %), DFL 2x4 Fb is 1000 instead of 900, `calcCL` clamps R_B at **10** (not the §3.3.3.7 limit of 50) which overstates F'b by 3–13 %, `calcCP` silently clamps l_e/d at 50 so a jamb at l_e/d = 80 gets 2.5× its real C_P, the jamb "Slenderness l_e/d ≤ 50" row is fed the clamped value and therefore can never fail, the king-stud wind model understates the wind force ~2× and can understate f_b by half for a tall opening, king studs get C_r = 1.15 they are not entitled to, and king-stud axial load defaults to zero.
2. There is no ASCE 7-16 §2.4.1 combination envelope anywhere: D, floor L, roof Lr and S are summed at full value into one load case, C_D is hard-wired (1.0 gravity / 1.6 wind), and a dead-load-only member is checked at C_D = 1.0 instead of 0.9.
3. Wind pressure has no declared basis; the C&C calculator hands this page **strength-level** ASCE 7-16 §30.3 pressures which are used unfactored in an ASD check (1/0.6 = 1.67× high — conservative, but it is not the code combination).
4. Whole checks are missing: deflection (IBC 2021 Table 1604.3) is absent entirely, the jamb-pack bearing on the bottom plate is absent, and stud bearing on the plate is absent; header bearing area ignores the jamb count.
5. Correct as written: `LBR` section properties, `CF_Fb`/`CF_Fc`, `useCF:false` for Southern Pine, all SPF No.2 values, DFL Fv/Fc⊥/Fc/E/Emin, the Eq. 3.3-6 and Eq. 3.7-1 algebra, c = 0.8, K_cE = 0.822, the 1.20 E'min/R_B² form, f_v = 1.5V/A, and the omission of C_D and C_b from F'c⊥.

## Open questions for the reviewer

1. **Wind basis (H-13).** Should the engine accept strength-level W and apply 0.6 internally, or accept ASD wind directly? The C&C calculator currently exports strength-level, so whichever is chosen, `sendToHeaders` in `asce716_cc_wind_calculator.html:1786-1794` must be changed in the same pass or the two calculators will disagree.
2. **King stud axial (H-11).** The plan says kings take "accumulated wall gravity on the stud's own tributary width". Does that tributary include half the opening (i.e. does the king pick up any of the header reaction), or does the jamb pack take 100 % of it? The current `kingAxial` cell has no defined meaning either way.
3. **Jamb unbraced length (H-7).** The code uses the full floor height; the physical trimmer runs only to the underside of the header. Use top-of-opening (less conservative, more correct) or keep floor height (conservative, simpler)?
4. **C_r on wall studs.** §4.3.9 requires a load-distributing element. Should the engine require a "sheathed" checkbox before granting 1.15, or is sheathing a safe blanket assumption for this calculator's scope?
5. **Stud pass limit (H-15).** Drop 0.96 to 1.0 per the plan, or keep 0.96 as an ARE house rule stated as a policy note rather than a code check?
6. **Roof Lr vs S (H-12).** The page has two separate roof inputs ("Roof Live / Snow (LL)" and "Snow Load") whose labels overlap. Do you want them kept as two independent effect cases (Lr and S, enveloped), or collapsed to a single roof case with a type selector?
7. **Adapter version (H-32).** Bumping the AREv2 adapter to version 2 will make `are-utils-v2.js:1501` refuse every existing saved file. Confirm the migration path before the fix phase.
8. **Registry status.** `app/lib/calcs.ts:399` still reads `status: "ready"` with `spec: "ASCE 7-22"`. Given H-1 through H-11, should it be flipped to `wip` now rather than at the start of Phase 2?
