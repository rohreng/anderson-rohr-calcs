# Auditor B — `stacked_shearwall_calculator.html` vs SDPWS 2021 + ASCE 7-16

**Target:** `C:\Users\nickh\OneDrive - Rohr Engineering\RE CODING\ARE Web Calcs\anderson-rohr-calcs\public\Calcs\stacked_shearwall_calculator.html` (1,071 lines, read end to end).
**Codes used:** SDPWS 2021 with Commentary (`...\Wood Codes\Special Design Provisions for Wind and Seismic.pdf`, © 2020, approved 2020-07-22) and ASCE 7-16 (`...\Analysis\ASCE 7-16.pdf`). Tables 4.3A / 4.3C / 4.3.5.6 and Eqns 4.3-5 through 4.3-9 are raster images in the PDF; extracted with `pypdf` and read visually. Hardware catalog numbers are another auditor's scope; only their *use* is audited here.

## Summary (5 lines)

1. **Seismic design is not implemented at all.** `designCase`, `species` and `wallWidth` are written to the save file and never read by any calculation (only occurrences: lines 213–227, 971–1011). Every sheathing capacity is the wind ASD value (nominal ÷ 2.0). Choosing "Seismic" yields capacities **1.40× the value SDPWS §4.1.4.1 permits** (÷ 2.8), with no warning.
2. **`calcCo` does not compute C_o.** It returns the Commentary's intermediate *sheathing area ratio* `r` (Eq. C4.3.5.6-2), not C_o (Eq. 4.3-6). The two differ in both directions — up to ~8 % unconservative at high α with tall openings (the shipped default model is in that band), and ~2.3× over-conservative at low α.
3. **`calcFloorData` accumulates plf, not force.** `v_total += V_j /(C_o,j·L_i,j)` summed across stories is not `(ΣV_j)/(C_o,k·L_i,k)`. A two-story example below gives **375 plf where the correct answer is 825 plf — a 2.2× unconservative sheathing and sill demand.** The overturning loop in the *same function* accumulates force-first and is correct, so the two outputs are internally inconsistent.
4. **Four gypsum-only entries and two over-strength two-sided entries are offered as perforated-wall sheathing**, which SDPWS §4.3.2.3 (WSP required) and §4.3.2.3(4) (nominal ≤ 2,435 plf) do not permit; there is no aspect-ratio check at all (aggregate `Li` only), no framing specific-gravity factor (Table 4.3A fn. 3), no 0.92 inside-face hold-down factor (fn. 10), no uplift anchorage `t` between hold-downs (§4.3.6.4.2.1), and no end-post check.
5. **`ΣL_i = 0` (or `L = 0`, or `ΣL_i > L`) returns "✔ All PASS"** with every demand silently zeroed. Load basis (ASD vs strength) is never declared, 0.6W / 0.7E / 0.6D are never applied, and roughly a dozen on-page code citations use SDPWS **2015** numbering or point at the wrong 2021 section.

**Scope note:** this audit covers strength/capacity checks against the sections named. Shear-wall deflection and story drift (§4.3.4), diaphragm and collector design, concrete anchorage (ACI 318 Ch. 17), anchor-rod steel, and construction-stage stability are outside it.

## Open questions for the reviewer

1. **S-2 sign of the error.** The code's `C_o` is unconservative only when `r > α/(3α−1)` (for α > 1/3). The shipped default sits just inside that band (1 % unconservative), but a low-α wall is penalised ~2×. Fixing it will make some existing designs *pass* that previously failed and some *fail* that previously passed. Does Nick want a migration banner on re-opened records, and does any issued drawing rely on the current numbers?
2. **S-3 magnitude in practice.** The 2.2× example assumes a solid upper story over a heavily perforated lower story. How common is that in ARE's stacked work? The answer decides whether this is a re-check-issued-projects event or a forward-only fix.
3. **S-12 dead-load relief model.** Plan item 10 says "force, not moment" on the chord. For a perforated wall the tributary dead load actually delivered to the *end chord* is not the whole wall's `w·L` — do we want (a) `0.6 × P_DL` on the chord's own tributary width, or (b) the full uniform stabilizing moment `0.3·w·L²`? (a) is defensible and much more conservative; (b) is what the current note claims to do but does not.
4. **S-11 load basis.** Confirm that legacy `V_floor` records should hard-block rather than assume ASD-wind — the plan says block, but every existing record will then require re-entry.
5. **ASCE 7-16 Table 12.2-1 row IDs in the plan.** The plan (item 8) cites rows **A.15 / A.16 / B.22 / B.23**. The standard's actual rows are **A.15** light-frame (wood) WSP (R = 6½, Ω₀ = 3, C_d = 4, h_n ≤ 65 ft in SDC D/E/F) and **A.17** "light-frame walls with shear panels of all other materials" (R = 2, Ω₀ = 2½, C_d = 2, 35 ft in SDC D, **NP in E and F**); **B.22** light-frame (wood) WSP (R = 7, Ω₀ = 2½, C_d = 4½, 65 ft) and **B.24** all other materials (R = 2½, 35 ft in D, NP in E/F). A.16 and B.23 are the **cold-formed steel** rows. Plan text should be corrected before Phase 2 wires the SFRS gate.
6. **Gypsum as a second face.** Retaining it per §4.3.5.4.2 requires the wind-only exception ("the combined nominal unit shear capacity… shall equal the sum of the sheathing capacities of each side") to be gated on wind, and the seismic case to use "two times the smaller or the larger, whichever is greater". Confirm both branches are wanted, or drop gypsum from this calculator entirely.
7. **C4.3.6.4.4 collector nuance.** "Where adequate collectors are provided to distribute shear, the average shear in the perforated shear wall above (e.g., equivalent to design shear loads), and not the increased shear for anchorage of upper story wall bottom plates to elements below, needs to be considered." This affects what the *floor below* receives at a stacked line. Should the calculator offer that as an option, or always take the conservative `v_max` path?
8. **S-18 floor ordering.** Is "+ Add Floor" adding at the bottom intentional (building up a model downward) or a defect? The fix differs.
